# 交互式主界面

`cfm` 不带参数运行就进交互模式：

```bash
cfm            # 或 node bin/cfm.mjs
cfm ui         # 显式进入
```

---

## 为什么做交互模式

命令行子命令对熟手很快，但对第一次用的人门槛很高 —— 得先读 `cfm help`，
记住 `cfm dns sync example.com --file dns.json --prune` 这种一长串。

交互模式把这些包成菜单，进去选就行。**两者并存**：交互是入口，
命令行是自动化接口，底层调的是同一套代码。

```
╭──────────────────────────────────────────────────────────╮
│  Cloudflare 免费额度工具箱                                │
│  cfm interactive                                          │
╰──────────────────────────────────────────────────────────╯
● 凭据正常 · 账号 7cfd2e90… · 3 个域名

你想做什么？
  ❯  01. 📊  看用量           各类资源用了多少、还剩多少
     02. 🩺  做体检           找出悄悄浪费额度的配置
     03. 🔍  全账号审计       zone 配置 + 资源占用 + 风险清单
     04. 📖  额度速查         免费额度对照表与踩坑
     05. 🧮  场景估算         这个用法能撑多少流量？
     06. ⚙️   配置与操作       DNS / 缓存 / R2 / Workers 等
     07. 🚀  初始化向导       新域名接入后的一键加固
     08. ❓  帮助             命令对照与文档
     09. 退出

↑↓ 选择 · 回车确认 · 直接按数字 · q 返回
```

## 按键

| 按键 | 作用 |
| :--- | :--- |
| `↑` `↓` | 移动光标（也支持 vim 风格 `k` / `j`） |
| `Home` `End` | 跳到首/末项 |
| `1`-`9` | 直接选中对应项（少按一次回车） |
| `回车` | 确认当前项 |
| `空格` | 多选时切换勾选 |
| `a` | 多选时全选 / 全不选 |
| `q` | 返回上一级；在主菜单按则退出 |
| `Ctrl+C` | 强制退出 |

## 安全设计

交互模式没有削弱任何安全约束：

1. **危险操作仍然要确认**。删除、清缓存、批量改配置都会先展示「将要做什么」，
   默认选项是「否」。
2. **只读命令不受影响**。体检、审计、用量查询直接执行，不需要确认 ——
   因为它们本来就不改任何东西。
3. **`--dry-run` 仍然可用**。交互里的批量操作先走一次 dry-run 预览，
   确认后才真正执行。
4. **非 TTY 自动降级**。管道 / CI 里跑 `cfm ui` 会明确报错并退出 2，
   不会卡在等输入上。

## 非交互场景怎么办

交互模式只是「人」的入口。要在脚本/CI 里用，仍然走命令行：

```bash
cfm usage --json | jq '.kv.byAction.write'
cfm doctor example.com --json
cfm dns sync example.com --file dns.json --yes
```

无参数运行时的行为也做了区分：

| 环境 | `cfm` 的行为 |
| :--- | :--- |
| 交互终端 | 进入菜单 |
| 管道 / CI | 打印帮助并退出 |

所以 `cfm | grep xxx` 不会挂住。

## 实现说明

交互逻辑拆成两层，便于测试：

```
src/lib/prompt.mjs
  ├── 纯函数层（可单测）
  │     handleSelectKey        按键 → 状态转移
  │     handleMultiSelectKey   同上（多选）
  │     computeRedraw          重绘的 ANSI 计算（防刷屏）
  │     renderSelect           菜单文本渲染
  │     renderMultiSelect
  └── 终端层
        Prompt.select / multiSelect / input / confirm / pause
```

`select()` 内部调用的就是那几个纯函数 —— **测的就是实际跑的代码**，
不是另写一份影子实现。

为什么这样拆：真实按键驱动需要 pty（Linux 用 `script`，Windows 没有），
CI 里难搭；而交互 bug 几乎都出在状态转移（越界、跳过 disabled、
0-based/1-based 混淆、重绘行数算错），这些都在纯函数里。

`scripts/ui-logic-test.mjs` 覆盖 43 项，含：
- 方向键回绕、跳过禁用项、全禁用时不动
- 数字键索引换算、超范围、指向禁用项
- 多选的空格/a 键语义、纯函数不改入参
- 重绘的光标回退与残留行清理
- 菜单结构完整性（每项都有 switch 分支、每个二级菜单都有返回项）

最后一条特别有用：**加菜单项忘了写 switch 分支**这种 bug，
只有用户点到那项才会暴露，而测试能提前抓住。
